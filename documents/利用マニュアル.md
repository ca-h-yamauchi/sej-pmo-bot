# SEJ-PMO Bot 利用マニュアル

**対象**: CA 社内（SEJ-PMO および Bot にメンションする案件 PM 等）  
**更新**: 2026-10-27  
**この文書**: Slack での使い方。コード・デプロイは [README](../README.md) と [デプロイ手順](GitHubデプロイ手順.md)。人間向けの読み用は同フォルダの `利用マニュアル.html`（ブラウザで開く）。

社内の作業台帳です。問合せ No.、Bot スレッド、シートの行内容は **SEJ へ共有しない**。

---

## 何をする Bot か

Slack でメンションすると、本文から情報を抜き出し、[問合せ管理スプレッドシート](https://docs.google.com/spreadsheets/d/16PlEFCHcnyqTtqEF0xa_N-ushSrwtGAN0VB6PL_3HZY/edit) に行を追加します。返信は同じスレッドに返ります。

| モード | いつ | 書き込み先 |
|---|---|---|
| **問合せ管理**（既定） | 1行目に課題キーワードがない | シート「問合せリスト」 |
| **課題管理** | 1行目に課題キーワードがある | シート「課題管理」 |

権限の付与そのものはしません。登録後の対応は PMO（山内・笠舞）が振り分けます。SEJ 側の操作が必要なときは、別途 Asana で依頼します。

---

## 基本ルール

1. Bot が入っているチャンネルでメンションする。
2. 本文は **1000 文字以内**（超えると登録しない）。
3. **1行目**だけがモード判定と、メール必須の例外キーワードの対象。2行目以降に「【課題】」と書いても問合せ扱いになる。
4. 1通で複数人・複数件書いてよい。行が分かれて登録される。
5. メールは `user@example.com` と書いてよい（Slack がリンク化しても Bot 側で平文に戻す）。

---

## 問合せ管理（アカウント・作業依頼）

キーワードは不要。対象者の氏名と、アカウント系ならメールを書く。

```
@Bot 佐藤太郎さんの Slack アカウント作成をお願いします。SREチーム、sato.taro@example.com
```

複数人:

```
@Bot 佐藤太郎さんと田中花子さんの Asana 追加をお願いします。sato.taro@example.com、hanako.tanaka@example.com
```

自分自身:

```
@Bot 私のアカウント作成をお願いします。アプリチーム、myemail@example.com
```

Bot が取るもの: 対象氏名、メール、タグ（最大5）、対応期日、オーダ番号・オーダ名（書いてあるとき）、問合せ者（送信者）。

新規行の進捗は「1.未着手」。以降のステータスはシートで手更新する。

### メールが必要なとき

タグに「アカウント管理」が付くと、対象者メールが必須です。無いと登録せず、再入力を求めます。

メールが本当に不要な依頼は、**1行目**に次のいずれかを書く。

- `メールアドレス無し`
- `メールアドレスは不要`
- `メールアドレスは有りません` / `メールアドレスはありません`
- `アカウント管理ではない` / `アカウント管理ではありません`

```
@Bot メールアドレス無し
〇〇さんの Asana アカウント状況を確認したい
```

本文にメールがあるのに「メールが必要」と返ることがある。そのときはメールを対象者の近くにもう一度書くか、1行目の例外キーワードを使う。

## 課題管理

**1行目**に次のいずれかを書く。

- `【課題】` / `[課題]` / `課題：`
- `【課題事項】` / `[課題事項]` / `課題事項：`
- `【SEJ案件課題】` / `[SEJ案件課題]`

```
@Bot 【課題】本番環境でログイン時にタイムアウトが多発しています。優先度 High。今週末までに一次切り分けしたいです。
```

複数件:

```
@Bot 【課題事項】
1. Slack の通知が一部メンバーに届いていない
2. スプレッドシートへの書き込みが稀に失敗する
```

Bot が取るもの: タイトル（20字以内の要約）、概要、カテゴリ/タグ、優先度（High / Mid / Low）、目標解決日、起票者。

担当者・最新状況メモは空欄のまま登録される。シートで手入力する。課題モードではアカウント管理のメール必須チェックはしない。

---

## 返信の見方

成功すると、登録件数とシートへのリンク、各件の要約が返る。認識が違えばシートを直す（Bot は既存行を上書きしない）。

よくある失敗:

| 返信 | すること |
|---|---|
| 1000 文字超過 | 短くして送り直す |
| 情報を正しく読み取れませんでした | 氏名・メール・依頼内容をはっきり書いて再送 |
| アカウント管理にはメールが必要 | 対象者メールを足すか、1行目に例外キーワード |
| エラーが発生しました + `error_id` | 下の「うまくいかないとき」 |

---

## PMO 向け（登録後）

1. シートで内容とタグを確認する。
2. CA 内で完結する作業はそのまま進める。
3. Asana / Slack / Box / Teams の権限が SEJ 側作業なら、古川様向け Asana サブタスクにする。問合せ No. は SEJ コメントに書かない。
4. 次世代 Slack / Jira / Confluence / Box は Asana 経由にしない。次世代アカウント手順に従う。

---

## うまくいかないとき

1. Bot がチャンネルに入っているか、メンションできているかを確認する。
2. Slack の返信にある `error_id` を控える。
3. [Cloud Logging](https://console.cloud.google.com/logs) でサービス `slack-bot-handler-us`（リージョン `us-central1`）を開き、`error_id=` で検索する。
4. コード変更や再デプロイが必要なら [README](../README.md) と [GitHubデプロイ手順](GitHubデプロイ手順.md)。

コンソールに Python を貼り付けて直さない。
